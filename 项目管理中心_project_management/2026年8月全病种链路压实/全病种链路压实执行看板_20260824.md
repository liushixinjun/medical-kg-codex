读取历史结果后必须按时间线区分，不能混用中间态和最终态：

## 2. 本轮一次性覆盖范围

| 模块 | 必须检查什么 | 合格标准 |
|---|---|---|
| 疾病层级 | 疑似诊断、具体分型、标准诊断 | 宽口径疾病可作为疑似诊断；具体分型才进入精确诊断和出院诊断；每个可回写诊断必须有 CDSS 标准诊断映射 |
| 检查/检验 | 初筛、鉴别排除、治疗前置、随访监测 | 不能只写疾病直连检查/检验；必须说明服务对象、诊疗阶段、推荐目的和优先级 |
| 鉴别诊断 | 鉴别对象、鉴别规则、所需检查/检验、结果解释 | 不能只有“主动脉夹层”这种对象标题；必须能回答“为什么鉴别、用什么排除、依据哪里来” |
| 治疗方案 | 方案、用药、手术、治疗处置 | 治疗方案标题只能作为知识入口；正式推荐必须落到具体动作和主证据 |
| 正式推荐 | 推荐陈述、推荐动作、主证据、主指南 | 只有推荐陈述指向推荐动作，且具备主证据/主指南时，才能进入正式 CDSS 推荐区 |
| 证据质量 | 原文、来源、页码/章节、摘要可读性 | 不能只看“有 Evidence 节点”；OCR/编码乱码、跨疾病兜底证据、来源不清都不合格 |
| 标准字典 | 诊断、检查、检验、检验细项、药品、手术、治疗处置、症状、体征、生命体征 | 图谱主名称优先使用 CDSS 标准字典；缩写和口语名进入别名；缺失项进入待注册清单，不伪造标准编码 |
| 历史兼容对象 | 旧关系、过程节点、审核残留、空壳节点 | 与临床知识无关的过程对象清理；仍有临床价值的对象必须迁移到新结构 |

## 3. 今日新增硬闸门

| 新硬闸门 | 原因 | 处理方式 |
|---|---|---|
| 证据文本可读性 | 8 月 18 日结构化 JSON 样板证据字段未检出乱码，但历史 Markdown 汇总报告存在乱码片段，说明“结构通过”和“展示报告可读”必须分开校验 | 正式推荐主证据必须人工可读；乱码证据不得作为医生端主依据 |
| 服务器读写健康 | 当前 Neo4j Bolt 握手失败，SSH 主动断开 | 服务器恢复后再执行写库和服务器复核；本地先完成审计和变更包 |
| 月计划同步 | 已发生交接记录有更新但月计划未同步 | 每次任务结束必须同步交接、踩坑、步骤记录、月计划和项目看板 |

## 4. 当前不再拆分的执行顺序

1. 用现有 8 月脚本和样板规则，形成全病种审计口径。
2. 补齐证据文本可读性、检查/检验用途、鉴别规则、治疗下游动作、正式推荐主证据五类硬闸门。
3. 生成待写库变更包和回滚清单。
4. Neo4j 恢复后一次性写入服务器并复核。
5. 复核通过后更新 Schema、SKILL、月计划、交接和踩坑日志。

## 5. 当前阻断与不阻断

- 阻断服务器写库：Neo4j Bolt 当前不返回握手，SSH 无法登录执行服务重启。
- 不阻断本地执行：规则审计、文件修正、变更包、回滚清单、证据污染筛查可以继续做。
- 不做无意义工作：不再反复给出零碎“下一步”；不再只用覆盖率百分比证明图谱质量；不再把疾病直连检查/治疗当正式推荐。

# Schema 结构与三来源融合评估

时间：2026-07-19 22:02:11
范围：现行 Schema、解析技能和服务器 Neo4j 只读盘点
本轮写 Neo4j：否

## 一、结论

现行医学维度并非整体过多，定义、症状、体征、检查、检验、诊断、鉴别、治疗、随访、证据和临床规则均有实际 CDSS 用途。真正的臃肿来自三点：V1.x 与 V2.x 两套结构并存、原文句子被过度实体化、同一证据和规则在多层重复连接。Schema V2.3 已将结构收敛为“目录—诊断—方案—具体项目”四层，并明确教材、指南和 CDSS 字典三类来源的职责。

## 三、必须保留的结构

1. 目录：顶层学科、疾病大类、可选展示分组。
2. 诊断：待分型疾病、具体分型、CDSS 标准诊断。
3. 疾病医学事实：定义、病因、机制、症状、体征、检查发现、检验细项、诊断、鉴别、风险、并发症、随访、预后和预防。
4. 方案：只保留辅助检查方案和治疗方案。
5. 具体项目：检查、检验、药品、手术/操作、其他治疗项目。
6. 决策：专病路径、阶段、临床规则、推荐陈述和来源裁决。
7. 来源：文档、章节和证据片段。

## 四、需要收口的结构

1. 停止新增并迁移 `Exam`、`LabTest`、`ExamIndicator` 和相关旧关系。
2. 将 `has_recommended_action` 全部按语义迁为阶段可选动作或正式推荐动作；正式推荐不得指向方案、诊断标准、风险分层、并发症或预后。
3. 删除疾病大类直连方案；将真正属于疾病的知识移到 `Disease`，原文句子回到 `Evidence`。
4. 取消方案套方案；总原则作为方案描述和证据，方案直接连接具体项目。
5. 证据只连接最精确事实/规则/推荐一次，页面通过查询聚合，不复制关系。
6. 临床规则仅保留可判断条件、鉴别条件、禁忌条件和推荐触发条件；纯知识描述回归医学事实或证据。

## 五、三来源统一原则

- 教材/专著提供稳定骨架。
- 指南/共识/路径提供场景化决策和推荐证据。
- CDSS 字典提供 UUID、编码、标准名称和已有基础限制候选，并接受二次校验。
- 同一概念只有一个正式实体；多个来源只增加证据和版本，不复制实体。

## 六、建议执行顺序

1. 先将本轮四层边界和三来源规则接入本地与服务器质量闸门。
2. 迁移 345 个旧实体和 14,237 条旧关系，生成回滚包后再写库。
3. 处理 14 条疾病大类错误方案和 94 条方案嵌套关系。
4. 规范临床规则与正式推荐终点。
5. 最后执行手术 V2 标准主数据迁移，避免把旧方案/旧手术混入新主数据。

验收目标：旧实体与旧关系为 0；疾病大类挂方案为 0；方案嵌套方案为 0；正式推荐终点全部为具体动作；同一概念不因来源重复建实体。

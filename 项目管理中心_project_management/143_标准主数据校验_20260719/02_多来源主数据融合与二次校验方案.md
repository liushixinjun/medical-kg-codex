# 多来源主数据融合与二次校验方案

更新时间：2026-07-19 21:03:07

## 1. 最终定位

Oracle/CDSS 既有字典不是天然权威标准，而是当前业务系统中的候选主数据和业务 UUID 来源。有效标志为 1 仅允许记录进入校验池，不代表名称、编码、别名、人群限制和医学含义必然正确。正式专科图谱必须把 Oracle、权威教材、诊疗指南、专家共识、监管批准药品说明书、官方编码标准和外部权威白名单资料联合使用。

大模型负责读取原文、术语归一、别名发现、语义冲突识别、候选匹配和质量检查；大模型自身知识不能作为证据。每个正式确认或纠正结果都必须能定位到 Oracle 快照或权威原文。

## 2. 六步校验链

| 顺序 | 校验内容 | 主要来源 | 通过结果 | 不通过结果 |
|---:|---|---|---|---|
| 1 | 候选获取 | Oracle 有效标志为 1 的记录 | 进入候选池 | 无效记录排除 |
| 2 | 技术质量 | UUID、编码、名称、空值、重复、字段格式 | 标记技术通过 | 进入字典问题清单 |
| 3 | 术语语义 | 标准全称、缩写、别名、同名异义、项目/细项边界 | 生成规范主名和别名 | 进入冲突队列 |
| 4 | 编码校验 | 官方疾病/手术编码标准、业务版本 | 编码与名称一致 | 标记编码冲突，不可回填 EMR |
| 5 | 临床内容 | 教材搭骨架；指南、共识和说明书核验适用人群、禁忌、时机和场景 | 形成有证据的医学属性 | 保持未覆盖，不允许猜测 |
| 6 | 图谱落地 | 本地增量包、审计、回滚、服务器复核 | 正式主数据和决策链可用 | 阻断写库或正式推荐 |

## 3. 数据来源分工

| 来源 | 负责内容 | 不负责内容 |
|---|---|---|
| Oracle/CDSS 字典 | 业务 UUID、现有编码和名称候选、有效状态、院内对接入口 | 不自动证明医学正确性和完整性 |
| 权威教材/专科专著 | 疾病概述、病因机制、临床表现、检查检验、诊断鉴别、治疗、随访、预后和预防骨架 | 不直接赋予指南推荐等级 |
| 诊疗指南/专家共识/临床路径 | 临床场景、适用人群、触发条件、禁忌排除、优先级、时机、推荐等级和证据等级 | 不替代业务 UUID |
| 监管批准药品说明书 | 药品标准名称、全局禁忌、特殊人群、用法剂量和安全警示 | 不替代具体疾病指南的场景优先级 |
| 官方编码标准 | 诊断和手术编码体系、版本、名称与编码语义 | 不提供完整临床诊疗知识 |
| 外部权威白名单 | 本地教材和指南未覆盖的权威补充 | 不允许未归档网页直接进入正式证据 |
| 大模型 | 抽取、归一、候选匹配、冲突识别、质量复核和检索建议 | 不能作为医学证据或最终权威来源 |

## 4. 正式使用状态

| 状态 | 中文含义 | 是否可进入正式图谱主数据 | 是否可用于 CDSS 预过滤/回填 |
|---|---|---:|---:|
| `unverified` | Oracle 候选尚未二次校验 | 否 | 否 |
| `validated` | 名称、编码和语义已通过交叉验证 | 是 | 是 |
| `conflict` | Oracle 与外部权威来源冲突 | 否 | 否 |
| `rejected` | 重复、错误或不适合作为标准项 | 否 | 否 |

人群限制另行记录 `dictionary_unverified`、`dictionary_verified`、`evidence_confirmed`、`governed_composite`、`source_conflict`、`not_covered`；只有已核验或有权威证据的状态才能执行患者预过滤。

## 5. 已发现的真实风险

1. ICD 字典 42,073 条有效记录中存在 1,314 组同名记录，不能仅按名称直接合并。
2. 检验细项存在 11 组同名和 27 组重复编码，需要结合单位、标本和所属项目判定。
3. 检验标本 117 条有效记录中有 38 条编码为空、12 组重复编码，不能原样批量入图。
4. 体征表只有 12 条且有 2 组同名，无法覆盖专科图谱体征体系。
5. 医学术语表存在 1,606 组同名记录，而同义词表有效记录仅 69 条，别名治理明显不足。
6. AMI、肥厚型心肌病、扩张型心肌病的 Oracle 记录可用于候选匹配，但需要核对编码版本、疾病层级和名称语义后才能正式确认。

## 6. 下一步执行顺序

先以 AMI 和心肌病为样板，生成 Oracle 候选、教材/指南术语、官方编码和现有 Neo4j 实体的四方对照表；修复可疑人群限制字段；验证疾病、标准诊断、症状、体征、检查、检验、药品、手术和治疗项目的二次校验流程。样板通过后再按疾病大类批量扩展，不直接全库复制 Oracle。

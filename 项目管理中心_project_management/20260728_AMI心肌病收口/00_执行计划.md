# AMI 与心肌病样板收口执行计划

执行日期：2026-07-28
执行范围：急性心肌梗死（AMI、STEMI、NSTEMI）与心肌病大类及其 11 个具体分型
执行目标：在不引入新实体类型、不引入新关系类型、不复用错误旧结构的前提下，形成可重复执行的样板验收基线。

## 一、固定边界

1. 疾病目录只负责组织，不承载临床方案。
2. 宽口径疑似诊断与具体分型均为 `Disease`，使用 `diagnostic_role` 区分。
3. CDSS 标准诊断使用有效标准字典记录，通过 `has_standard_diagnosis` 落地。
4. 检查、检验只允许以下标准路径：
   - 疾病 → 辅助检查方案 → 检查项目 → 检查发现
   - 疾病 → 辅助检查方案 → 检验项目 → 检验细项
5. 正式推荐必须通过“推荐陈述 → 推荐动作/评估目标 → 证据”表达。
6. 不新增 `display_layer`；临床展示与治理属性由字段白名单和业务查询场景区分。

## 二、一次性执行内容

1. 冻结本轮疾病范围、服务器基线、变更清单和回滚数据。
2. 先编写自动测试，覆盖错误直连、疾病角色必需槽位、标准诊断映射和正式推荐链路。
3. 将可唯一确定父级的错误路径迁移到标准路径，并在同一事务中物理删除错误直连。
4. 核验 AMI 三层与心肌病三层的目录、临床分型和标准诊断落地。
5. 按疾病角色检查必需知识槽位；只使用已存在且可追溯的教材/指南证据补齐，证据不足时保留阻断，不凭模型猜测。
6. 本地审计全部通过后才写入 Neo4j。
7. 写库后执行同口径复测和全量回归，输出修复前后对比报告。
8. 将本轮新增闸门同步到 Schema、SKILL、步骤记录和踩坑日志。

## 三、四项独立验收结果

| 验收项 | 含义 | 通过要求 |
|---|---|---|
| 知识内容完整性 | 疾病角色所需的定义、临床表现、诊断、鉴别、治疗等是否存在 | 必需槽位缺口为 0 |
| 标准身份完整性 | 可诊断疾病是否能落到有效 CDSS 标准诊断 | 应映射未映射为 0；无有效字典时明确阻断 |
| 路径可用性 | 检查、检验、治疗和推荐是否能按标准路径下钻 | 错误直连、空方案、孤立标准项目为 0 |
| 正式推荐就绪度 | 推荐是否有场景、动作/评估目标和证据 | 正式推荐硬阻断为 0 |

四项分别统计，禁止再用一个“覆盖率百分比”掩盖具体缺口。

## 四、写库条件

以下任一条件不满足时停止写库：

- 回滚数据未生成；
- 错误路径无法唯一确定父级；
- 新增内容无教材、指南、共识、说明书或有效标准字典依据；
- 目录、宽口径诊断、具体分型角色混淆；
- 正式推荐缺少动作/评估目标或证据；
- 测试或本地审计未通过。
